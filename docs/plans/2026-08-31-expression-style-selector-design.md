# 表情功能三画风设计

## 目标

“表情包”和“表情包夺舍”共用一个画风问卷，提供三种互斥模式：表情包原生画风、角色锚点原画风、萌粒画风。角色锚点始终是 Image 1、唯一身份来源和最高优先级参考；画风选择只改变整张图的绘制媒介，不得改变发型、五官、身体比例、服装、配饰和标志配色。

## 数据与提示词

两个工作流都保存 `style` 配置，值为 `meme`、`anchor` 或 `mengli`，默认 `meme`。生成策略拆成不可变身份锁和可切换画风锁，并在最终提示词入口组合，避免界面选项被旧的全局“仅萌粒风”再次覆盖。普通表情包的 `meme` 模式使用适合聊天缩略图的原生反应图语言；表情包夺舍的 `meme` 模式使用 Image 2 的完整画风。`anchor` 模式沿用 Image 1 的线条、上色、材质、明暗和简化程度；`mengli` 模式使用 Skill 规定的断线手绘与轻微错版平涂。

## 约束与验证

表情包夺舍无论选择哪种画风，都必须保持参考图的构图、裁切、动作、表情、文字、背景块和笑点，同时彻底替换原主体的头部与身体身份。自动测试分别检查两个工作流的三种模式，确保三者都含身份锁；仅 `mengli` 含 `MENGLI ONLY`，另外两种分别含原生表情和锚点原画风策略。非表情工作流继续默认萌粒风。发布前运行完整测试、代码检查、Next.js 构建和单文件站点构建。
